# 倍音の誤選択・短い音符の分断への対応

評価日: 2026-09-06。比較元はPR #15マージ時の `d2b48d5`。初版の合成・PJS報告は履歴として残す。本報告は追加修正の証拠であり、Issue #13全体の達成を意味しない。

## 再現と実装計画

1. 弱い基音と強い第2倍音を持つ音で、最初のYIN閾値通過だけを選ぶ方式のオクターブ誤りを再現する。
2. 旧YIN、MPM、窓長、低域通過、候補間比較を同じPCMで比較し、誤差と負荷で採用する。
3. 短い孤立音と発声境界の倍音候補を、原解析値を残した派生音符で限定的に扱う。休符・100ms音・内部の実跳躍を回帰検証する。
4. マイク入力処理を含むChromium経路、許諾PJS実録音、ビルド、独立レビューを実施し、未検証条件を明示する。

## 採用・不採用

- YINのCMNDF全候補を比較し、最良値との差が0.01以内かつ絶対閾値0.15未満の局所最小のうち、最短周期を選ぶ。補間・55–1000Hz・連続MIDI・歌80ms/話60ms・10ms hop・有声閾値は維持。
- 窓延長、MPMへの変更、絶対閾値を0.1へ下げるだけの案、低域通過（800/1200/1800Hz）の試行では対象の倍音誤りが残り、不採用。候補差0.02も拡張合成集合で大誤差7.5–11.875%が残った。0.01を採用する。
- 検出器のパラメータ選定には評価対象を使っている。以下は調整集合での比較であり、未知の話者・音源への汎化精度ではない。
- 派生音符だけで、無声に挟まれた30ms未満の有声区間を除外する。さらに有声区間の先頭/末尾50ms以下が、隣接する80ms以上の安定音より約12半音高い場合だけ、12半音下げる。cents変動・時刻・原framesは保持し、無声を跨いで補間しない。内部の短い音程変化、100msの音、短い低音は維持する。
- 本物の50ms以下の高い音が発声境界にある場合との完全な識別はできない。これは限定的な再生・楽譜用の補正であり、正解F0の確定ではない。原音・原軌跡は確認可能。
- ブラウザのnoiseSuppressionは対応制約だけ `ideal: false` を要求する。echoCancellationは従来の `ideal: true`、autoGainControlは従来の `ideal: false` を維持。実適用値は既存UIに表示し、未報告やブラウザによる無視を無効化成功とみなさない。

## ブラウザ入力処理の比較

Docker Chromiumの仮想マイクへ、130Hz→260Hz、振幅比0.1の基音と第2倍音、休符を持つ同じWAVを入力。実物のマイクや部屋の雑音ではない。

| noiseSuppression | echoCancellation | 観測 |
| --- | --- | --- |
| true | true | 持続部が260/520Hzへ誤推定 |
| true | false | 同じ倍音誤りが残る |
| false | true | 持続部は130/260Hz。休符の低音や内部の余計な音符も一部実行で観測 |
| false | false | 持続部は130/260Hz。3音になる実行と、余計な音符が出る実行の両方を観測 |

反復確認で、仮想マイクの取得PCMに元WAVにない10ms連続ゼロが挿入され、窓内の周期を壊していた。新しいChromiumプロセスでも起きるため、プロセス隔離だけでは解消しない。したがって余計な短音をechoCancellation由来と断定せず、その変更は不採用。持続部の再現根拠があるnoiseSuppressionだけ無効要求にした。物理雑音への抑制効果を確認した選択ではなく、雑音や他の音源を拾いやすくなる可能性が残る。録音中のアプリ再生は従来どおり停止する。

回帰は区別する。仮想マイクはgetUserMediaの設定・持続部の音名・UI/楽譜を検証。全音符の区切りは、既知WAVをAudioBuffer→MediaStreamDestinationで同じAudioContext時計からCaptureSessionへ渡し、実AudioWorklet→Worker→再解析→音符化で3音を検証する。後者はブラウザ内の合成ストリームであり、実マイク入力処理の証明ではない。入力自体が欠落したときの完全な復元は未対応で、無音を勝手に埋めない。

## 実録音評価との区別

既存の許諾PJS歌声5件・日本語話声1件を、同じ解析/音符化経路で再実行。出典と許諾は [real-audio-sources.md](real-audio-sources.md)。追加の取得・音声公開はない。今回の集計は [pitch-continuity-pjs-results.json](pitch-continuity-pjs-results.json)。フレーム正解F0・有声ラベルがないため、音符数の減少を精度向上と断定しない。通常話声の有声割合約16.9%という制約も残る。

利用者提供の録音でも両モードの修正前後をローカル比較し、独立したPraat raw AC推定との照合と、本番ピアノschedulerによる試聴ファイル生成を実施した。独立推定は正解ラベルではない。提供音声・派生PCM・フレーム値・音声の識別情報をGit/PR/公開配布物へ含めない。

追加の聴き比べでは、話し声の「鍵盤に丸める」に残る細切れ感が指摘された。同じ話し声解析を「元のズレを残す」で再生した比較版に利用者の好評価が得られたため、歌声と話し声の初期再生設定をともに「元のズレを残す」へ揃えた。丸めの手動選択と楽譜の半音表記は維持。これは提供された1録音の聴感確認で、解析精度や一般的な会話の完成を証明しない。
