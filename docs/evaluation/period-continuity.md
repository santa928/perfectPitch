# 下方オクターブ候補の限定的な連続性比較

評価日: 2026-09-07。比較元は PR #16 を含む `1a8d319`。追加の歌唱録音で下方オクターブへの飛びを観測した。前回の母音で得られた改善を維持し、本物の短い音程変化を消さない範囲で改善する。Issue #13 / REQ-012 の完全達成を意味しない。

## 要件差分と実装計画

| 対象 | 状態 | 今回の扱い |
| --- | --- | --- |
| REQ-001〜011 | 維持 | Vite/TypeScript、公開基盤、連続音高、録音/再生、楽譜、検証条件を維持 |
| REQ-012 | 維持 | 追加の実録音で再評価。下方オクターブへの限定的対応を追加し、残存不具合を記録 |
| 保留・削除 | なし | 未検証条件は未達のまま追跡 |

1. 同じPCMで候補閾値、時系列の優先、波形特徴の条件を比較する。
2. 公開可能な合成音で揺らぐ周期強度と真の100ms音を作り、短音を消す案を除外する。
3. 選択した処理を共有解析へ実装し、chunk境界、無声、Worklet/Worker経路を確認する。
4. 提供録音・許諾録音の再解析、試聴用生成、独立レビューとPRを行う。

受け入れ条件: 既存のクリーン音程・休符・連続centsを維持し、合成の短い実跳躍を音符として保持する。非対象: 正解メロディへの矯正、UIによる代替、マージ・公開・Issueクローズ。性能目標: 既存の歌/話150/120ms因果追従、1窓CPU p95 10ms以内を維持。リスク: 曖昧な本物の下降が1フレーム遅れる可能性を明示し、補正の自己継続を禁止する。

## 比較と採用理由

- 従来の最良CMNDFとの差0.01は、周期ごとの強度変化で低い候補が少し有利になると、倍の周期へ切り替わる場合がある。
- 閾値の一律拡張は、前回の弱い基音を上の倍音へ取り違えるケースを再導入したため不採用。
- 直前音の無制限優先は、提供録音の飛びを大幅に減らした一方、合成した本物の100ms下降も消した。ノイズ量の推定、有声区間100msの半周期構成との比較を加えても、ノイズや倍音構成が変わる下降を消す反例があり不採用。試聴用に生成した強い補正版も採用しない。
- 採用は**最大1フレーム（10ms）の候補比較**。通常選択が直前音より約1オクターブ低いときに限り、近接する上の実候補を比較する。最良誤差×4+0.01、上限0.1、直前音との差100c未満、下の候補との差1200±60cという条件を使う。話し声でも補正候補には周期性0.9超を要求する。上限0.15では強い有色ノイズ下の短い低音をさらに10ms短くしたため、弱い候補による上書きを除外した。
- 候補自身の補間周波数・周期性を返し、有声閾値は維持する。補正した結果を次の補正の根拠に使わず、自己継続を禁止する。非有声フレームで履歴をリセットし、無声の補間を行わない。状態は検出1件のみで、追加の先読みや窓延長はない。
- これは短い誤判定への限定的な処理で、長く続く曖昧さは残る。本物の下降が最大1 hop遅れる代償がある。音符数を減らすこと自体を精度の証明としない。

## 合成音による比較

再現方法:

```sh
docker compose -f docker-compose.test.yml run --rm unit node --experimental-strip-types scripts/benchmark-period-continuity.ts
docker compose -f docker-compose.test.yml run --rm unit
```

[集計JSON](period-continuity-results.json)に、両sample rate・両mode・複数周波数/seedの周期強度変化と、白色/AR(1)ノイズ・音色変化を含む100msの上下移動を同じ窓で比較する結果を保存する。strictは履歴なしのPR #16の選択、contextualは今回の1フレーム上限付き選択。

比較harnessは既知の無音校正と固定energy floorを使うため、実アプリの環境雑音校正の検証ではない。50c超誤差と未検出を分けて集計する。`correctRunMs` は100ms区間内の連続正解フレーム長で、最終音符の長さや正解率ではない。最終音符保持は別のpipelineテストで確認する。調整/回帰集合であり、未知話者への汎化精度ではない。CPU測定はDocker内の検出器処理で、実機のI/O・描画を含まない。

| 条件 | mode | 50c超フレーム: 従来→今回 | 未検出: 従来→今回 |
| --- | --- | --- | --- |
| 周期強度変化24例 / 2376フレーム | 歌 | 692→580 | 2→2 |
| 周期強度変化24例 / 2376フレーム | 話 | 750→606 | 9→9 |
| 100ms音・ノイズ・音色変化168例 / 中央504フレーム | 歌 | 53→65 | 19→19 |
| 同上 | 話 | 67→69 | 0→0 |

強度変化の誤りは減ったが、短音の中央フレーム誤差は増えた。1フレームの遅れを伴う選択であり、全条件の精度が改善したとは言わない。30ms以上の連続正解区間がない例は歌23→22、話14→13。従来30ms以上あった区間が今回30ms未満になった例はこの集合では0件だが、今回も35/336例に不足がある。正解の短音を常に復元できる状態ではない。

周期強度変化の各ケース内で測定したCPU p95の最大値は、歌2.195→2.124ms、話1.490→1.411ms。計測揺れを含み高速化の主張には使わない。既存のクリーン固定音・±30c・低音・跳躍の回帰テストも通過した。前回の640音全検出器比較は履歴として残し、今回は履歴付き経路に合わせた比較を追加している。

## 実録音とブラウザの区別

提供された2録音を両modeでローカル再解析し、前の母音の結果を維持すること、追加歌唱で一部の飛びが減ることを確認する。正解F0ラベルはない。長い下方オクターブ判定と短い途切れは残る。提供音声・派生音声・個別フレーム・識別情報はGit/PR/配布物に含めない。提供録音を使った調整なので、独立した評価集合ではない。

ブラウザはDocker Chromiumで、既知の合成PCMをAudioBuffer→MediaStreamDestination→実AudioWorklet/Workerへ入力し、ライブと停止後再解析の一致、同じ取得PCMの履歴なし推定との比較を行う。物理マイクや端末確認とは区別する。既存の仮想マイク・再生・楽譜のテストも共有解析の回帰として実施する。

既存の許諾PJS歌声5件・日本語話声1件も再実行した。出典・許諾は [実録音の出典](real-audio-sources.md) のままで、追加取得はない。無音校正付き条件の有声フレーム数は全6件で前回と同じ。連続音符数はPJS012歌声が41→39、ほかは40/29/57/13/12で不変。通常話声の有声割合約16.9%という限界は残る。F0正解ラベルはなく、件数変化を精度改善とみなさない。再現コマンド:

```sh
docker compose -f docker-compose.test.yml run --rm unit node --experimental-strip-types scripts/evaluate-real-audio.ts output/period-pjs-results.json
```
