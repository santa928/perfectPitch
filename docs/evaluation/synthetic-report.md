# 合成PCMによる検出器比較（2026-09-06）

これはPR #14時点の比較記録。追加の弱い基音条件と現在の候補選択方式は [pitch-continuity.md](pitch-continuity.md) を参照。

## 結論と採用

YINを採用し、歌80ms／話し声60ms、両方10ms hopとした。MPMも全てのクリーン条件を通過し、cents精度はYINより高い。ただし両者とも目標20 centsを十分下回り、このDocker計測ではYINのp95処理時間が短かった。80msは20dB雑音条件のp95誤差が40/60msより小さかったため歌に採用。話し声は低音の周期を含みながら跳躍の因果遅延を60msに抑えた60msを採用する。これは今回の有限合成集合からの選択で、実声で最適と証明したものではない。

10ms hopはCPU p95がhop内に収まり、100ms音を複数フレームで保持でき、境界量子化を10msに抑えるための設計判断。別hopでの端末性能比較は未実施。検出窓中央の時刻と、右端までPCMが届く因果遅延を区別する。

## 方法

- 実行: `docker run --rm -v "$PWD:/app" -w /app node:24-bookworm-slim node --experimental-strip-types scripts/benchmark-pitch.ts`
- 環境: Node 24.18.0 / Linux arm64 Docker。wall-clock `performance.now()`、各検出器・窓につき10回warmup。端末CPU・Worker転送・UI・音声出力遅延を含まない。
- 同一窓内では全検出器へ同じFloat32 PCMを渡す。窓40/60/80ms。sample rate 44.1/48kHz。
- 周波数55, 82.41, 98, 220, 440, 1000Hz、±30/0 cents（55–1000Hzを外れる端点のみ除外）。振幅0.01/0.25、位相0/1.3rad、倍音重み[1], [1,.5,.25], [.3,1,.4]。各窓384有声例。
- 非周期64例/窓: 無音16、白色雑音24、一次低域通過雑音24。固定乱数seed=93。
- 追加雑音: 各窓×10/20dB SNRで24有声例。周波数全6種、両sample rate、両位相、倍音[1,.5,.25]。窓条件のノイズ列は独立だが各検出器は同じPCM。
- 旧検出器はmain b67b836の`autoCorrelate`をそのままfixtureへ抽出。旧UIの閾値・平滑化はかけない。比較は検出器単体であり、旧アプリ全体の有声誤検出率とは異なる。
- median/p95は周波数を返した例だけの絶対cents誤差。missと50 cents超/オクターブ誤りの分母は全有声例。false voicedは非周期例で周波数を返した率。periodicityは確率ではない。
- YIN: 固定supportの差分、累積平均正規化、閾値0.15、放物線補間。MPM: NSDF、ゼロ交差後の局所peak、最大peakの90%以上かつ0.85以上の最初のpeak、放物線補間。FFT高速化はしていない。

## 時間・音符・原値

- 0.35–0.55sの220Hz→0.55–0.75sの440Hz、休符、0.85–0.95sの82.41Hz、休符、1.05–1.15sの98Hzを解析。両sample rateで4音を保持し、100ms短音を削除・反復分割しなかった。
- 歌の最初の正解フレームが利用可能になる因果遅延は40/80/70/70ms、話し声は40/60/50/60ms。収録UIの入力latencyは別。無声との境界では窓混合によって音符の長さは入力100msより短くなる（正確なonset/offset検出は保証しない）。
- tはPCM窓中心のサンプル時計。127サンプルずつのpushと一括offlineの全値一致をテスト。最後の不完全hopはゼロ埋めせず省略する（最後の完全窓の右端から停止までhop未満）。窓中心に音符を置くため、録音末尾の最大約半窓分まで音符終端が届かない場合がある。
- 最初300msは校正状態。低periodicity窓の下位25% RMSをfloorとし、有声中は更新しない。無音中のみ緩やかに追従する。声を出して校正すると適切な周辺noise floorは得られないため、静かにするUI案内が必要。
- 原framesは無丸めの連続MIDI。音符生成のコピーだけ、両隣が一致する単一フレームの12半音飛びを補正する。実際に継続するオクターブ跳躍は保つ。連続モードは±30 centsのcontourを保持、丸めのみ0.65半音のヒステリシス。無声フレームは休符。

## 証拠と限界

`synthetic-results.json`は比較全表、時間event、個別失敗を持つ機械可読記録。`tests/analysis.test.ts`は低音/±cents、chunk不変性、校正/雑音、原frames非破壊、短音/休符/跳躍、vibratoの回帰を確認する。

これは合成音のみ。人声の息成分、子音、二重声、強い倍音、周期的空調音、人が開始直後に発声する場合、iPhone/Android実機は精度を保証しない。周期的環境音と声の区別には限界がある。許諾実音声と実機マイクの検証をこの合成結果で代用しない。
