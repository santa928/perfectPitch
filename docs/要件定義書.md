# 要件定義 — Issue #13 リニューアル

## 目的

鼻歌を録り、そのメロディをピアノで確認し、同じ内容のカタカナ付き五線譜から演奏できる体験を目指す。後続のユーザー承認で中心目的を明確化した。普通の話し声・原音・連続音高の既存機能は維持する。既存Vite/TypeScript、GitHub Pages基盤を維持する。

承認元: [Issue #13](https://github.com/santa928/perfectPitch/issues/13)。初版要件を以下で追跡する。仕様の削除/保留はせず、評価未完了を「達成」に読み替えない。

## 性能・精度目標（実装前に設定）

- 55〜1000Hz、44.1/48kHz、位相/振幅/倍音を変えたクリーン合成音: median誤差5c以下、p95 20c以下、大誤差50c超/オクターブ誤り1%以下、取りこぼし5%以下。
- 合成無音・非周期雑音の有声誤検出1%以下。
- 100ms音を保持。歌/話の因果追従150/120ms以内。Dockerの1窓CPU p95 10ms以内。音声I/O・転送・描画遅延は別途扱う。
- 描画30/60/120fpsでも解析のsample時刻と音符長が変わらない。±30cは連続モードで保持、半音丸めのみ変化する。
- 最大60秒PCM。録音/再解析/音源の失敗と停止後に操作可能状態へ戻る。
- 録音後の解析待ちを許容。Dockerで10秒の録音を5秒以内に解析することを今回の性能目標とし、実端末の速度は別途確認する。ライブの追従目標は維持。解析タイムアウトは60秒、停止応答済みのPCMは分析だけの失敗では破棄しない。

[合成評価](evaluation/synthetic-report.md)には達成値と強い雑音の未達を併記する。旧検出器単体と新pipeline全体を同じ誤検出率として混同しない。

## 非対象

原曲採点/正解メロディの取得、音源分離、声とピアノの同時ライブ再生、共有・アカウント、別repo/フレームワーク移行、不要なbackend、未承認のクラウド音声送信・課金。楽譜ではPDF出力、自動拍子/調推定、全面的なDAWは含まない。新変更のmainマージ・本番公開・Issueクローズは実施しない。

## サービス品質改善の追加受け入れ条件

- 新方式は音符の活動と発音を推定し、元PCM・連続F0と区別する。学習モデルが全録音で優れると仮定せず、元の推定へ戻せる。2推定を切り替えても、それぞれの手直しを保持する。
- 最初に多歌手7録音を固定して3人を開発、4人を候補固定後の最終確認へ分ける。人手F0・2人の音符注釈・公式譜面BPMを混同しない。未提供BPMはnull、不確実な仮120は自動推定成功に数えない。
- 開発前目標のPJS記譜前F1平均+10ポイントと各曲5ポイント超悪化なしは、その条件を満たした場合のみ達成とする。合成短音の保持や終了時刻の悪化を平均値で隠さない。最終4歌手は音高+発音F1がほぼ同じでも、終了込みF1は悪化しており全面置換は不採用。
- ファイルの長さをdecode前後に検証し、冒頭の有声を校正として捨てない。入力中止/壊れたファイル/モデル取得失敗で既存データを破棄しない。モデルは明示操作時だけ取得し、音声を外へ送信しない。
- 音符の編集・追加・削除は480PPQ・128分音符の倍数のtick内で重複を拒否する。タイ・休符・同音再発音とピアノ/MIDIが一致する。Undo/Redo、未編集時の音価再推定と編集後の演奏速度変更を画面文言と同期する。
- 性能目標は10秒入力5秒以内、60秒入力30秒以内。推論だけ・初回取得・再標本化・記譜・全経路を分離し、Dockerブラウザと物理端末を区別する。モデル/WASM容量、初回/再試行/中止の挙動を記録する。
- 自動テスト・実録音評価・実ブラウザ操作・iPhone/Android実機は別に記録する。未実施のOS中断や実機マイクを達成扱いにしない。

## 楽譜追加の受け入れ条件と性能目標

- 録音後に実データから五線譜と固定ドのカタカナを表示。無音に偽の音符を出さない。
- 4/4、最短128分音符、仮BPM120（40〜240の整数で変更可）、最初の検出音を1拍目と明示する。
- 小節内の音符と休符は1920 tick（480PPQ）、同じ論理発音の分割だけタイを付ける。表現不能な原音符は対象と理由を残し、未配置数と要確認を表示する（REQ-024）。
- 原PCM・連続音高・既存ピアノの発音時刻は変更しない。再解析/再録音/設定変更中の古い描画は破棄する。
- 60秒・BPM240で最大60小節、描画は1ページ4小節まで。ライブラリは必要時だけ読み込む。
- 375px/1280pxで音名の重なり・SVGの下端/右端の欠け・ページ全体の横はみ出しを検査する。
- 既存REQ-001〜010の削除・保留はない。楽譜追加を音声解析の精度改善として扱わない。

### 鼻歌メロディの追加受け入れ条件

- 歌声の派生音符列は、揺れによる過分割と本物の100ms音を比較して選択する。原PCM・連続centsは変えず、元の検出精度改善と音符化の改善を区別する。
- 同じScoreからピアノ・五線譜・固定ドを生成。タイだけを継続音にし、休符・同音再発音を区別。譜面のテンポ/全小節長で再生し、原録音長で切り捨てない。
- テンポの候補と仮120を区別し、40〜240の手入力で譜面とその再生を同期。原音/従来ピアノの時間は変えない。
- 譜面再生は録音・原音等の再生・閉じる・テンポ変更・ページ離脱で停止。音源失敗後に再試行できる。
- 合成フレーム、合成PCM、実録音、ブラウザ操作を分けて評価。提供録音の聴感と「譜面を演奏したら元の旋律になるか」は未完了として追跡する。
- 性能: 最大60秒の入力、4小節単位の描画を維持。新しい音符推定の処理時間を別途記録し、モデル方式の速度と混同しない。

## リスクと対策

複数テンポ評価の追加受け入れ条件:

- 解析結果を見る前に80/120/180 BPMの3曲を固定し、元音声を伸縮しない。出典/許諾/ハッシュを記録する。
- 公式譜面は作曲上の基準として評価専用に使う。本番に曲名・正解BPM・音符を渡さず、移調・DTWで誤りを隠さない。
- 音高＋発音、音高＋発音＋終了、音高列の編集距離、テンポ採用成否、生成譜面を曲別に報告。仮120が基準120と一致しても自動推定成功とはしない。
- 調整2曲と候補固定後の1曲を区別し、生成楽譜・ピアノをローカルに保存して確認する。提供音声とPJS原音・譜面はGit/公開配布物に含めない。
- 音程検出の誤りと量子化後の再打鍵を区別する。REQ-024で短い別音の省略とその前後の同音結合を廃止し、検出済みの別発音と実休符を保持する。
- 性能: 本番解析や依存を増やさず、既存60秒上限と4小節描画を維持。Docker計測と実機性能を混同しない。

以下の既存リスクと対策も維持する。

- 低音の観測時間と短い抑揚: 窓長を比較し歌/話を分ける。境界の時間誤差を明示。
- 周期的環境音と声の区別: 保証しない。物理環境音試験と複数音源は未完了。
- マイク/音声中断・非対応: 明示停止・エラー、勝手に再開しない。
- 音源取得/デコード: timeout/再試行。外部JSを実行しない。簡易音で代替しない。
- メモリ: 60秒上限、PCMコピーの用途を限定。実端末でのピークメモリは未計測。
- 実音声ラベルの範囲: 検出有声割合を「精度」や「検出率」と呼ばない。Vocaditoの人手F0付き評価は限定コーパスの結果で、本人録音や実環境全般の精度保証に広げない。
- 採譜の不確実性: 表示は近似と明示。BPMを調整可能にし、未配置・要確認の原音符と理由を報告。半音表記は♯へ統一し、調性の推定はしない。
- 鼻歌の強いビブラート/短音・深いトレモロ: 音符の誤統合/誤分割が残り得る。音量谷だけで発声意図を保証せず、元の声と比較できるようにする。テンポが不規則・音符が少ない場合は候補の確定を避ける。

## 自然なピアノ再生の追加受け入れ条件

- 初期設定と譜面再生は鍵盤単位の固定音程を使い、声のcontourで滑らせない。元サンプルの打鍵と減衰を再生し、長音を持続ループしない。
- 途中再開で打鍵をやり直さない。離鍵後120msの余韻を持たせ、原音時計・音符の開始/終了・譜面・MIDIの音価を変えない。連続音高は明示選択で維持する。
- 同じ譜面・テンポで前後のPCMを比較し、不正値・クリッピング・発音方式を確認する。聴感の好みと自動採譜精度は数値検査から断定しない。
- 性能: 新規依存・音源配信先・取得ファイルを増やさず、使用鍵盤だけをデコードして再利用する。最大88鍵のキャッシュと取得済みデータは終了時に解放する。物理端末の再生遅延・ピークメモリは未測定。
- リスクと対策: 短い休符へ余韻が重なるため離鍵後の消音を120msに制限。長音はサンプル終端で無音になることを仕様に明示。音源の一部が欠けても既存鍵盤は使え、失敗した鍵盤は再取得できる。生ピアノの共鳴、ペダル、強弱の多層サンプル追加は今回の非対象。

## 短い低音への急落補正（REQ-021）

| 区分 | 今回の要件差分 |
| --- | --- |
| 維持 | REQ-001〜020。元PCM/原解析値、30ms以上の観測低音、休符、滑らかな下降、自然なピアノ、編集/MIDI/任意再採譜を維持 |
| 追加 | REQ-021。前後の安定した声へ20ms以内に戻る大きな急落だけを、表示/音名/ピアノ/標準採譜で限定補正 |
| 保留・削除 | なし。実機マイクと提供PCMでの効果は未確認 |

受け入れ条件は10〜20msの急落抑制、雑音を含む100msの実音・原値・休符の保持。前後の根拠がない境界低音や長い誤推定の自動訂正は非対象。同形の本物の極短い低音を消すリスクがあるため、時間と前後の支持条件で限定する。性能目標は既存60秒上限と10ms hopを維持し、派生補正は線形走査・近傍確認とする。[検証報告](evaluation/brief-pitch-drops.md)を参照。

## 長音欠落の修正（REQ-022 / Issue #20）

| 区分 | 要件差分 |
| --- | --- |
| 維持 | REQ-001〜021。原PCM、sample clock、休符・実短音・跳躍、編集済みScore/MIDI、自然なピアノを保持 |
| 追加 | REQ-022。初期雑音後の明瞭な長音を有声判定で失わず、一次候補・雑音量・分類理由を診断できること |
