# 実装仕様 — 声を見てピアノで聴き直す

PitchFrameは `t, frequency, midi, rms, periodicity, state` を保持する。tは録音冒頭を0とした解析窓中心の秒。stateはvoiced/unvoiced/uncertain/silence/calibrating。periodicityは周期性指標で、正解確率ではない。整数鍵盤番号は派生値。受理されなかった周波数とMIDIはnullであり、直前の音を引き延ばさない。

歌80ms・話60ms窓、10ms hop。開始300msの低周期性窓の下位25% RMSを初期noise floorにし、有声判定できた即発声は校正中も保持する。無音と判定され、かつ周期性0.6未満のときだけfloorをゆっくり更新する。周期信号を誤って雑音学習し続けない。

候補Hzあり・周期性0.97以上の窓は、現在のRMS×sqrt(1−周期性)を残差振幅の目安とし、effective floorを `min(noiseFloor, max(0.001, 残差振幅))` にする。0.001は未校正時の初期値で、この回復だけでそれ以下へ感度を上げない。静かな校正から既に得た小さいfloorは維持する。通常の周期性閾値（歌0.9/話0.85）とRMS条件 `max(0.001, effective floor × 2.8)` を満たす現在候補だけ採用する。前の音高のコピー・持続時間による補間はない。低周期性で低音量の窓はsilence、周期性はあるが採用できない窓はuncertain。ただし絶対音量下限0.001未満はsilence。周期性は残差の厳密な雑音推定や確率ではなく、周期環境音と声を識別するVADでもない。

`PitchFrame.initialGate` は開発用の一次判定記録（candidateHz、candidatePeriodicity、noiseFloor、effectiveNoiseFloor、requiredRms、reason）。reasonはperiodic / periodic-recovery / calibration / below-energy / aperiodic / ambiguous。録音後の候補追跡や短窓再測定は外側のfrequency/periodicity/stateを変更することがあるが、initialGateは元窓の根拠として保存する。最終判定理由と混同しない。通常画面へ数値を追加せず、実モジュールを呼ぶ `scripts/benchmark-sustained.ts` でローカルJSONへ出力できる。音声・診断情報を自動送信しない。

YINは閾値0.15未満の最初の谷への即決を避け、全候補の最良CMNDFとの差0.01以内にある最短周期を補間する。倍音が強い合成音での比較・残る限界は [追加評価](evaluation/pitch-continuity.md) を参照。

下方オクターブの曖昧さに対して、直前の有声候補との差が1200±100cのときだけ、最良CMNDF×4+0.01（上限0.1）未満の局所最小も比較する。代替候補は直前音から100c未満かつ元候補の上方1200±60cに限定し、その候補自身の周波数と周期性を返す。補正候補には話し声でも周期性0.9超を要求する。前の値をそのまま複製せず、通常の有声閾値は緩和しない。補正結果は次フレームの補正根拠に使わないため、連続する補正は1 hop=10msまで。非有声フレームと録音開始で履歴を解除する。真の音程変化への追加遅れはあり得るため、100ms音・音色変化・ノイズで回帰を確認する。長い誤判定の解消は保証しない。[比較・不採用案](evaluation/period-continuity.md)。

PCM Float32 monoを最大60秒保持。48kHzで11.52MB/コピー、192kHz上限では46.08MB/コピー。停止時の連結/Worker転送/原音AudioBuffer等で複数コピーが必要であり、ブラウザ全体の厳密なメモリ上限ではない。再解析はコピーを転送し、元のPCMをdetachしない。MediaRecorderは採用せず、ブラウザ別の記録コーデック・decode可否への依存を解消。MP3ピアノのデコード互換性は別途必要。

## 録音後の見直し

ライブは上記の因果解析を維持する。停止後は同じCMNDF計算から得た候補を有声区間ごとに追跡する。候補はライブ値と、その上方1200±60cかつ誤差が `min(.1, live誤差×4+.01)` 未満の波形上の谷のみ。各候補の相対誤差の対数と、隣接音高差に対する弱い遷移コスト（1半音あたり0.1、12半音で上限）を足し、全区間から経路を復元する。20ms以上、音高幅50c以内でまとまっている観測は変更しない。真の短音を消す無制約の追跡は不採用。

両端が有声で音高差2半音以内、80ms以下のuncertain区間だけを40ms窓で再測定する。全フレームが周期性0.9以上、両端の間の予測音高から75c以内、RMSが両端の小さい方の35%以上という条件を満たした場合だけ、再測定した連続Hzで回復する。予測値を音程としてコピーしない。silence/unvoiced/calibratingは復元しない。意味上の子音と休符を完全に識別できる保証はなく、合成の無声境界も別に検証する。

録音サンプル、フレーム時刻、通常のライブ窓長・hopを維持する。進捗は実際の窓処理・候補追跡・再測定からWorkerが通知し、UIタイマーで模擬しない。停止後の値はライブの暫定値と異なり得る。[比較と残存限界](evaluation/offline-review.md)を参照。

## 音符と再生

- 歌声・話し声ともに「ピアノ（鍵盤の音程）」が初期設定。声の種類を変更するとこの設定へ戻る。「声の揺れを聴く（連続音高）」は再生設定から手動選択できる。
- ピアノ音符はstart/end/midi/contourを持つ。時間は録音と共通の秒。100msグリッドに丸めない。
- 無声・不明・欠落で音符を区切る。半音境界には0.65半音のヒステリシス。同音が休符を挟む場合は別音。
- 通常のピアノは半音へ丸め、対象鍵盤の元サンプルをループなし・固定playbackRateで再生する。3msの立ち上がりでクリックを抑え、サンプル自体の打鍵と減衰を残す。離鍵時刻から120msで消音する。音符区間・原音時計・譜面・MIDIの長さは変えず、再生完了の通知だけ余韻まで待つ。途中再開は元サンプルの経過位置から再生し、打鍵をやり直さない。長音はサンプル末尾で自然に無音になる。
- 明示した連続モードは従来どおりサンプルを持続ループし、細かなズレ、ビブラート、しゃくりをcontourとしてplaybackRateへ反映する。通常の鍵盤では出せない中間音を含む。譜面再生は上の選択にかかわらず通常のピアノを使う。
- 原解析値は無変更。両隣の有声音が一致する孤立した10msのオクターブ飛びを音符化時に補正。継続する実跳躍を補正しない。
- 表示/音名/ピアノ/標準採譜共通で、10半音以上の急落が20ms以内に元の音から0.5半音未満へ戻り、前後それぞれ約30msの安定有声区間を持つ場合だけ、前後の連続MIDIを時刻に沿って補間する。周波数も同期した派生値にし、原frames/PCM・時刻・音量・周期性は保持する。15ms超のフレーム間隔、無声、不明を跨がない。録音中は後続の支持音が揃うまで暫定値。同形の本物の20ms以下の大きな低音の動きとは完全に識別できない。30ms以上の低音、開始/終端の低音、滑らかな下降はこの補正の対象外。任意モデルの再採譜結果や手動編集済み音符は変更しない。
- 30ms未満の孤立した有声区間は発音しない。同じ有声区間の先頭/末尾50ms以下が、隣接する80ms以上の安定音より約12半音高い場合は、派生値だけ12半音下げる。上記急落補正の対象外の内部跳躍・100ms音・休符は維持。50ms以下の本物の高い境界音を区別できない場合がある。ピアノ操作可否と案内は派生音符の有無に合わせる。
- 最後の不完全hopはpaddingせず省略。窓中心による音符化のため末尾約半窓分が短くなる可能性がある。
- 再生開始時のAudioContext時刻 + 原音offsetでカーソルを算出。描画fpsは記録・音符時間に影響しない。
- 元の声/ピアノの切替は停止して先頭へ戻す。手動停止は位置を保持。再録音開始時は既存再生/ロードを停止。
- SoundFontのデータ部分だけをJSONとして読む。通常のピアノはA0〜C8の88鍵のうち使う鍵盤だけ、連続モードは従来のA1/A2/A3/A4/A5のうち必要な基準鍵だけをデコードする。データと成功済みAudioBufferを同じプレイヤー内で再利用する。20秒timeout、取得・デコード失敗後は再生ボタンで再取得できる。古い処理の失敗を新しい再生へ反映しない。外部スクリプトの実行・代替発振器はなし。

## 状態とエラー

記譜の丸めで短い別音が0 tickとなり、その前後が同じ鍵盤かつ丸め後の端点が接する場合、元の音符列も連続しているときだけ1イベントへ結合する。省略区間内を含め実際の隙間があれば結合せず、同音の明示的な再発音（丸めで省略された同音も含む）も結合しない。省略音数はそのまま報告する。これは表示と譜面再生の不要な再打鍵を防ぐ修正であり、元の連続Hzや音符推定器を変更しない。

楽譜はready以降に開ける独立パネル。歌声は`extractMelody`、話し声は`buildNotes(..., 'rounded')`の派生音符を使う。最初の検出音の秒時刻を原点として16分単位へ丸め、共通Scoreを表示と「譜面どおりに聴く」に使う。上のピアノ設定は楽譜に影響しない。休符を補完し、各小節を16 tickにする。小節や拍で分割された同一イベントだけをタイで繋ぐ。同音の別発声は繋がない。近似表示であり、グリッド未満の音/休符が消える場合がある。省略音数は表示し、譜面再生も同じ省略を反映する。

鼻歌の音符推定は連続有声島だけを対象にする。各整数鍵盤のコストは半音差の二乗（上限4、10ms相当へ正規化）、音が変わるコストは2＋0.3×半音差（差は12で上限）。全区間の経路を復元して同じ鍵盤のフレームをまとめる。これらは音符化の比較で選んだ目的関数であり、Hzの再測定や正解確率ではない。30ms未満の孤立有声島は発音しない。null/uncertain/unvoiced/silenceと時刻欠落を埋めず、原フレームを変更しない。強いビブラート内の短い半音変化が消える反例は残る。

一定鍵盤の区間に、直前最大100msの音量ピークの30%以下へ落ち、20〜80msの谷を経て、回復開始から40ms後に70%以上へ戻り約30ms続く変化がある場合、再上昇位置で同音を打ち直す。左右80ms以上の区間を要求する。80ms窓でRMSがなだらかになるため谷の直前だけを基準にしない。深いトレモロとの区別は保証しない。既存の連続音高ピアノにこの規則は適用しない。

テンポ候補は4音以上の開始/終了を40〜240 BPMの16分グリッドと比較して順位付けする。候補の平均二乗誤差に加え、隣接発音間隔の80%以上がグリッドから0.16tick以内であることを採用条件とする。十分に揃わなければ仮120。候補にも倍/半分等の曖昧さがあり、拍子・調・弱起は自動推定しない。手入力は40〜240の整数で、変更時は譜面の再生/読み込みを停止し、同じScoreを更新する。

譜面再生は専用VoicePlayerで譜面の0tickを0秒とし、全小節長を再生長へ指定する。正規のタイで繋がる連続同音だけを1回の発音へ結合し、休符/同音再発音を維持する。小節外、不正tick、重複、不正MIDIは変換時に拒否する。元録音の長さで切り捨てない。原タイムラインのカーソルは譜面時計へ流用しない。原音側の再生・録音・再解析・テンポ変更・パネルを閉じる・画面離脱で譜面再生を止め、譜面再生開始時は原音側を停止する。音源取得失敗後はボタンから再試行可能。譜面の音源も既存のSoundFontをデータとして取得する。

中央ドはド4、異名同音は♯へ統一し、小節内の臨時記号解除にはナチュラルを付ける。各小節の音高中央値でト音/ヘ音記号を選ぶ。カタカナは下の共通行へ揃え、音名の実測必要幅に安全余白を加える。SVG実寸から上下の領域を決定し、狭い画面は小節内スクロール。1ページ4小節までとし全録音を一度にSVG化しない。

楽譜モジュールはdynamic import、Bravura/Academicoフォントはデータとして同梱。ロード/フォント失敗はパネル内で再試行を案内。待ち中の再録音・設定変更・閉じる操作は世代番号で古い結果を破棄し、録音・再生操作を妨げない。

idle → requesting → recording → analyzing → ready → loading → playing。ファイル入力はidle/readyからimporting→analyzing→ready。ファイル処理を中止した場合は旧データに戻る。

- requesting中はキャンセル可能。遅れて権限が許可されても旧要求は破棄する。
- analyzing中は「分析中」と実進捗を表示し、録音/再生/モード変更を無効化する。上限60秒でタイムアウトする。
- recording中は再生しない。停止してマイクを解放してから再解析する。
- loading中は停止・音源切替・再録音でキャンセルでき、遅い応答が再生を再開しない。
- 権限拒否・Worklet/Worker失敗・音源取得/デコード失敗は文言と操作可否を同期して表示する。
- 停止応答後の分析だけが失敗した場合、完全なPCMを保持し、派生framesを空にして分析エラーを表示する。元音声再生と再解析が可能。停止応答失敗・録音中断・キャンセルはこの回復対象ではない。
- 背景化では録音を停止し、許可待ちはキャンセル、再生は停止する。復帰後はユーザー操作を必要とする。

## 対応/未検証

AudioWorklet/Workerを採用し、ScriptProcessor/rAF解析のフォールバックは設けない。窓処理時間とDocker Chromiumの実経路で採否を評価し、モバイル端末の負荷・互換性比較は未完了。弱い基音を失うケースを避けるためnoiseSuppressionは対応制約のみideal false、echoCancellationは従来のideal true、autoGainControlは従来のideal falseを要求する。実適用値はMediaStreamTrack.getSettingsでUIへ表示し、未報告値を無効化成功とみなさない。物理雑音での回帰は未検証。

検証は [evaluation/verification.md](evaluation/verification.md) に集約。APIサーバー、音声送信、永続化、採点はない。

## ファイル入力・任意の再採譜・編集

ファイルは20 MiB以内とし、Blob URLのaudio metadataを読んで60秒以内を確認してからdecodeする。成功/失敗/中止でURLと要素を解放する。OfflineAudioContextのdecodeAudioDataで48kHzにし、多チャンネルは平均する。decode後も長さ・finite PCMを検証する。ファイルの再解析は`calibrate:false`を保持し、先頭300msを除外しない。元マイクは従来どおり校正する。Workerに渡すPCMはコピーし、abort・遅い応答・再入力で元音声がdetachしない。

任意の再採譜はBasic Pitch公式ONNXを22050Hz monoの43844サンプル窓で処理し、重複を除いた音符活動88鍵・onsetを固定DPへ渡す。波形の候補・曲名・正解譜面・正解BPMをモデルに与えない。F0の代替ではなく派生音符の別候補であり、モデルは無声子音を音符の中に含める場合がある。純粋な休符の誤延長や100ms跳躍の欠落は残る。パラメータ、モデルSHA、公式時刻式、比較の条件は[モデル評価](evaluation/service-quality-models.md)を参照。標準推定は変更しない。

モデルとONNX RuntimeのWASMは同じサイトから、任意操作のときだけロードする。1 Worker/1スレッドで実行し、終了・中止時にWorkerを解放する。失敗時に旧推定を維持し、再操作で新しいWorkerから試行できる。WASM/mjsは固定npmパッケージから起動/ビルド時に生成し、モデルとlicenseは同梱する。外部の音声APIは使わない。

ScoreEditorはタイを同じ再生規則で結合した論理音符のコピーを持つ。音高21〜108、整数tick、正の長さ、小節総長内、非重複だけを受け入れる。編集後に2の累乗音価へ再分割し休符/タイを再構成する。安定ID、50件のUndo/Redo、元推定へのresetを備える。原音/原F0は不変。推定切替では各編集内容を保持する。元音声からの再解析/ファイル読込の成功、録音開始で破棄する。再解析・読込の失敗や中止では直前の音符編集を残し、声の種類の切替失敗では最後に成功した種類へ戻す。

テンポは未編集時に録音時刻から音価を再計算し、編集後はtickを固定して演奏速度だけ変える。その違いを画面で明示する。不正なテンポ中は譜面再生・編集・MIDI保存を止め、前の有効な編集内容を保持する。

MIDIはSMF format0、480PPQ、4/4、program0のピアノ、velocity96を使用する。scoreToPianoのタイ・休符・同音再発音を共有し、同時刻はnoteOff→noteOn順、EOTは最終小節末。原音originをMIDI冒頭に加えない。声・カタカナ・譜面画像は含まず、保存は利用者のダウンロード操作だけで行う。

長音再生は有限サンプルの枯渇を避けるため、attack後の持続区間をゼロ交差に寄せ、末尾10msのcrossfade付きでnote.endまでloopする。通常サンプルでは0.35〜1.3秒、短いサンプルでは長さ25〜75%を基準とする。音楽サンプルの加工であり、元ピアノ録音の自然な減衰をそのまま再現するものではない。sourceとgainは自然終了/停止の両経路で解放する。
